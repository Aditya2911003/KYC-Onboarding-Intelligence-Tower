# Decisions

Each open choice made while building the project, and why.

| # | Decision | Why |
|---|---|---|
| 1 | **Default date range = all simulated dates**; KPI deltas show "n/a" until a shorter range is picked (Period presets: last 12/6/3 months). | Keeps the headline numbers identical to the README (100,000 cases, 74.9%) on first load; a relative default would silently shrink the population. Deltas are one click away. |
| 2 | **AS_OF = 2026-06-30 for every time-based metric**, including review overdue (50,620), even though the brief's 49,828 matches the extract date 2026-06-24. | One snapshot date across the warehouse and the simulation; the difference is explained in `known_data_issues.md` and the claims table carries both numbers (C06, C06b). |
| 3 | **Overdue = more than 365 days** (`date_diff('day', last_updated, AS_OF) > 365`). | Literal reading of "more than 12 months"; exactly 365 days is not overdue (tested). |
| 4 | **Document key = (customer_id, doc_type)**, not DocumentID. | DocumentID collides across customers (13,533 surplus rows); the natural key is unique. Reported as a `warn`, not a `fail`, because it is a source quirk the model handles. |
| 5 | **Age check accepts age at the extract date or at AS_OF** and warns on the 1,693 AS_OF differences. | Age is as of the extract; recomputing it would change the source silently. Works on the full data and on the sample (whose latest `LastUpdated` differs). |
| 6 | **Selectable donut built from scatter markers.** | Plotly pie slices emit no selection events in Streamlit's `on_select`, verified in a headless browser; markers on a ring look like a donut and support click-to-cross-filter. |
| 7 | **Canonical filter state in `flt_*` keys, widgets in `w_*` keys.** | Streamlit discards widget state when a page does not render the widget; canonical keys survive navigation and can be written by cross-filter clicks. |
| 8 | **Cross-filter toggles** (clicking the only selected value clears it) and chart keys include a nonce. | Power BI behaviour; the nonce clears the chart's own selection so a filter is applied exactly once per click. |
| 9 | **Slicers apply to case-level visuals only.** Rules, AI benchmark, ML and DQ pages show the slicer bar (report-level state) with a caption saying it does not apply. | Those datasets have no case, date or channel dimension; filtering them would be fiction. |
| 10 | **Channel slicer and opened-date slicer are labelled "(SIMULATED)".** | The date slicer filters every page, so the simulation disclosure must be on the slicer itself. |
| 11 | **Marts exclude names, DOB, document numbers and OCR text**; Customer 360 shows a profile without the name. | Privacy hygiene even with synthetic data; a test fails if any mart gains such a column. |
| 12 | **Customer 360 only by exact ID** (regex `^C\d{6}$` checked before querying); five example IDs from the current slicers are shown as hints. | No browsing of the customer table on a public app; hints keep the demo usable. |
| 13 | **Case tables capped at 5,000 rows; CSV export capped at 5,000 rows with a `data_notice` column "SYNTHETIC DATA - not real customers"** and file names prefixed `synthetic_`. | Spec requirement; a column is safer than a comment line, which breaks CSV parsers. |
| 14 | **ML uses ordinal-coded categoricals on numeric splits** instead of HGB native categorical support. | SHAP's TreeExplainer produced values that failed the additivity check with native categorical splits; with ordinal codes SHAP passes and accuracy is unchanged in substance (95.5% vs 95.4%). SHAP is only shown when the check passes. |
| 15 | **AI detector is rule-based and reference-grounded** (sentence diff + outcome stance), not a trained classifier. | A trained text classifier would score ~100% on 25 templates by memorisation; transparent rules make the "by construction" point explicit and need no ML dependency in the pipeline. |
| 16 | **Named WINDOW clauses have unique names per file** (`w_stage`, `w_month`) and SQL files run statement by statement. | DuckDB's parser scopes named windows per script, so two statements both defining `w` fail when run as one script. |
| 17 | **Headline finding computed on all cases**, independent of slicers, on Executive and Controls. | The headline must not change when a reviewer plays with filters; the KPI cards and insight strip below it do. |
| 18 | **Flatness rule**: a chart is labelled FLAT when the max–min spread across groups is under a stated threshold (2 pp default; 1 pp for document and AI rates; 5 pp for analysts; 10 pp for monthly breach). | Makes "no signal" a computed, testable statement instead of an opinion. |
| 19 | **Illustrative 90% target** on the review gauge. | A gauge needs a target; it is labelled illustrative because the data has none. |
| 20 | **Streamlit custom subdomain `kyc-onboarding-control-tower.streamlit.app`** used for the README badge. | Only AUTHOR_NAME, GITHUB_USERNAME and LINKEDIN_URL may remain as placeholders; DEPLOY.md tells the deployer to claim that subdomain (or update the badge). |
| 21 | **Tree items clipped in the PDF brief** were completed as: `.gitignore` also ignores `.ruff_cache/`; `requirements-dev.txt` adds scikit-learn, SHAP, pytest, ruff, notebook and screenshot tooling; Makefile targets `setup, sample, etl, test, lint, app, screenshots, notebook, all` (+ `raw`, `ml`, `etl-sample`, `ml-sample`, `clean`); the smoke test is `tests/test_app_smoke.py`. | The PDF's code blocks were cut at the right margin; these are the evident completions. |
| 22 | **Extra files beyond the tree**: `tests/conftest.py`, `tests/__init__.py`, `app/__init__.py`, `etl/__init__.py`, `ml/__init__.py`, `docs/screenshots/mobile_executive.png`. | Needed for fixtures and package imports; the mobile shot documents the phone-width layout. |
| 23 | **Pinned versions are the ones installed and tested** (Streamlit 1.64.0, DuckDB 1.5.6, pandas 3.0.2, Plotly 7.1.0, PyArrow 25.0.1). | "Latest stable, pinned to what was tested." |
